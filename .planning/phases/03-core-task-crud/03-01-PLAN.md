  <behavior>
    - _td_resolve_task_id with valid prefix returns full UUID
    - _td_resolve_task_id with no-match prefix prints error, returns 1
    - _td_resolve_task_id with ambiguous prefix prints error with match count, returns 1
    - todo add "Buy milk" creates task, prints "Created task XXXXXXXX"
    - todo add (no args) prints usage error, returns 1
  </behavior>
  <action>
1. Append `_td_resolve_task_id` function to `lib/_td_core` (after existing functions). Implementation:
   - Takes two args: `$1` = tasks_file path, `$2` = ID prefix
   - Uppercase the prefix with `${2:u}` for case-insensitive matching
   - Use JXA via osascript to filter `data.tasks` where `t.id.toUpperCase().indexOf(prefix) === 0`
   - Pass prefix via `TASK_PREFIX` env var and file content via `JSON_DATA` env var (same pattern as _td_storage)
   - Return cases: "ERROR:not_found" → error + return 1, "ERROR:ambiguous:N" → error + return 1, else print full UUID
   - See 03-RESEARCH.md Pattern 2 for reference implementation

2. Create `commands/td-add` (no .zsh extension, no function wrapper -- autoload convention):
   - Collect all positional args as title: `local text="$*"`
   - Validate non-empty, else `_td_error "Usage: todo add <title>"` + return 1
   - Call `_td_storage_init`
   - Get tasks file path: `_td_storage_list_path`
   - Call `_td_storage_add_task "$tasks_file" "$text"` capturing UUID
   - Print confirmation: `_td_success "Created task ${task_id:0:8}"`
   - See 03-RESEARCH.md Code Examples td-add for reference

<task type="auto" tdd="true">
  <name>Task 2: Create td-ls command with formatted output</name>
  <files>commands/td-ls</files>
  <read_first>lib/_td_storage, commands/td-add</read_first>
  <behavior>
    - todo ls with tasks shows columnar output: ID (8 chars), Status, Priority, Title
    - todo ls with no tasks prints "No tasks yet. Run 'todo add' to create one."
    - Output header line contains "ID" and "Title"
  </behavior>
  <action>
Create `commands/td-ls` (no .zsh extension, no function wrapper):

1. Call `_td_storage_init`
2. Get tasks file: `_td_storage_list_path`
3. Use JXA to format output INSIDE osascript (avoid JSON parsing in zsh -- per research Pitfall 5):
   - Read file content into JSON_DATA env var
   - JXA script: parse data, check `data.tasks.length === 0` → return `__EMPTY__` sentinel
   - For each task: format as tab-separated line: `id.substring(0,8) + \t + status + \t + priority + \t + text`
   - Return all lines joined with newline
4. Handle empty case: if output equals `__EMPTY__`, print friendly message via `_td_success "No tasks yet. Run 'todo add' to create one."` and return 0
5. Print header: `printf "  %-10s %-8s %-10s %s\n" "ID" "Status" "Priority" "Title"`
6. Split output on newlines, for each line split on tabs, printf with same column widths
7. Use `while IFS=$'\t' read -r id task_status priority title` to parse tab-separated JXA output

IMPORTANT: Do not use `local status=...` -- use `task_status` (zsh reserved variable conflict, per Phase 2 decision).
