Add resize handling to `_td_interactive` (requirement UX-08):

1. **Add redraw flag global** at top with other globals:
   ```zsh
   typeset -g _TD_UI_NEED_REDRAW=0
   ```

2. **Add TRAPWINCH function** inside `_td_interactive_run`, BEFORE the input loop (after `_td_interactive_create_windows`). Must be defined as a function (not trap command) so zcurses signal handling cooperates:
   ```zsh
   TRAPWINCH() {
     _TD_UI_NEED_REDRAW=1
   }
   ```

3. **Add resize handler function** `_td_interactive_handle_resize`:
   - Destroy all existing windows via `_td_interactive_cleanup_windows`
   - Call `zcurses clear stdscr redraw` then `zcurses refresh stdscr` to let zcurses detect new LINES/COLUMNS
   - Recreate windows via `_td_interactive_create_windows`
   - Re-render via `_td_interactive_render "$list_name"` (list_name must be accessible — see step 5)
   - Reset `_TD_UI_NEED_REDRAW=0`

4. **Add redraw check in the timeout branch** of the input loop (after the `if zcurses input` block, in the else/fallthrough path when timeout fires with no key). The timeout is 200ms (line 572). Add:
   ```zsh
   if (( _TD_UI_NEED_REDRAW )); then
     _td_interactive_handle_resize
   fi
   ```

5. **Make list_name accessible to resize handler**: Change `local list_name` to `typeset -g _TD_UI_LIST_NAME` at the top of `_td_interactive_run` so the resize handler can pass it to `_td_interactive_render`. Update all references to `list_name` in the function to use `_TD_UI_LIST_NAME`. Also update `_td_interactive_handle_resize` to use `_TD_UI_LIST_NAME`.

6. **Adjust selection after resize**: In `_td_interactive_handle_resize`, after re-rendering, call `_td_interactive_adjust_selection` to ensure cursor is still valid if terminal got smaller and fewer rows are visible.

7. **Clean up TRAPWINCH in always block**: Add `unfunction TRAPWINCH 2>/dev/null` in the always block before `_td_interactive_cleanup_windows` to avoid leaking the trap handler.

Important: Do NOT use `trap 'code' WINCH` — use the zsh `TRAPWINCH()` function form which is more reliable with zcurses.

2. **Create `_td_interactive_show_help` function**:
   - Calculate overlay dimensions: width = min(50, COLUMNS - 4), height = min(18, LINES - 4)
   - Center position: y = (LINES - height) / 2, x = (COLUMNS - width) / 2
   - Create zcurses window: `zcurses addwin helpwin $height $width $y $x`
   - Add to `_TD_UI_WINDOWS+=(helpwin)`
   - Draw border: `zcurses border helpwin`
   - Draw title centered on row 1 (bold): `Help`
   - Draw keybinding lines starting at row 3, col 2 (left column = key, right column = description):
     ```
     Navigation
       j / Down     Move down
       k / Up       Move up
       h / Left     Previous column
       l / Right    Next column

     Actions
       s            Cycle status
       d            Mark done
       x            Delete task
       o            Open ref URL

     General
       ?            Toggle this help
       q            Quit
     ```
   - Draw "Press any key to close" dim at bottom row (height - 2)
   - `zcurses refresh helpwin`
   - Set `_TD_UI_HELP_VISIBLE=1`

3. **Create `_td_interactive_hide_help` function**:
   - If helpwin exists in zcurses_windows: `zcurses delwin helpwin`
   - Remove helpwin from `_TD_UI_WINDOWS`: `_TD_UI_WINDOWS=(${_TD_UI_WINDOWS:#helpwin})`
   - Set `_TD_UI_HELP_VISIBLE=0`
   - Re-render board: `_td_interactive_render "$_TD_UI_LIST_NAME"`

4. **Add ? key to input loop case statement**:
   ```zsh

       _td_interactive_hide_help

     fi
     ;;

     _td_interactive_hide_help
     continue
   fi
   ```
   This means when help is up, pressing j/k/s/etc first closes help, then the next press does the action.

6. **Handle help window during resize**: In `_td_interactive_handle_resize`, add: if `_TD_UI_HELP_VISIBLE`, set it to 0 (the helpwin will be destroyed with cleanup_windows). The user can press ? again after resize.
