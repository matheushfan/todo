  <action>
    **Create `lib/_td_interactive`** -- the zcurses engine library (autoloaded, file body = function body). This is the core of Phase 12. Structure:

    **1. Data loading function `_td_interactive_load_data`:**
    - Takes tasks_file path as argument
    - Single JXA call (reuse _td_board's __COL_SEP__ grouping pattern) to extract: statuses array AND tasks grouped by status
    - Each task line: `id\tpriority\ttags\ttext\tref` (tab-separated, add ref field)
    - Store results in typeset -g arrays:
      - `_TD_UI_STATUSES=()` -- status names in order
      - `_TD_UI_COL_TASKS=()` -- associative array keyed by `col_idx,row_idx`, value = tab-separated task line
      - `_TD_UI_COL_COUNTS=()` -- task count per column
      - `_TD_UI_TOTAL_TASKS=0`
    - Called ONCE at startup. Never in the render loop. Per Pitfall 3: JXA is ~27ms/call, must not be called per-render.

    **2. Render function `_td_interactive_render`:**
    - Uses zcurses windows for layout. Create these windows in init, reuse in render:
      - `header` window: row 0, full width, height 1. Shows: list name centered, bold
      - One window per kanban column: `col1`, `col2`, `col3`... positioned side by side below header
        - Height = LINES - 3 (header + separator + status bar)
        - Width = (COLUMNS / num_cols) -- equal distribution, minimum 20
        - Each column window: border drawn via `zcurses border`, status name at top row via `zcurses string`
        - Tasks rendered below status name, one per row: `[priority_char] id_short text_truncated`
      - `statusbar` window: last row, full width, height 1. Shows: `list_name | N tasks | q:quit`
    - zcurses attr for colors:
      - Priority: `zcurses attr win +bold red/black` for high, `yellow/black` for medium, `green/black` for low
      - Status headers: `zcurses attr win +bold cyan/black`
      - Status bar: `zcurses attr win reverse`
      - Dim for IDs: `zcurses attr win dim`
    - Use `zcurses move win row col` + `zcurses string win text` for each cell
    - End with `zcurses refresh` for all windows in one call: `zcurses refresh header col1 col2 ... statusbar`
    - If terminal too narrow (col_width < 15), show centered message "Terminal too narrow" instead of columns

    **3. Main engine function `_td_interactive_run`:**
    - TTY gate first (per Pitfall 8): `[[ -t 0 ]] && [[ -t 1 ]] || { _td_error "Interactive mode requires a terminal"; return 1; }`
    - Terminal size check: `(( LINES < 10 || COLUMNS < 40 )) && { _td_error "Terminal too small (min 40x10)"; return 1; }`
    - Get tasks file: `_td_storage_init && local tasks_file="$(_td_storage_list_path)"`
    - Get active list name: `local list_name="$(_td_storage_active_list)"`
    - Load data: `_td_interactive_load_data "$tasks_file"`
    - zcurses lifecycle using tetriscurses always-block pattern:
      ```zsh
      zmodload zsh/curses || { _td_error "zcurses module not available"; return 1; }
      {
        zcurses init
        echoti civis                # hide cursor
        zcurses clear stdscr redraw
        zcurses refresh stdscr

        # Create windows (call _td_interactive_create_windows)
        _td_interactive_create_windows

        # Initial render
        _td_interactive_render

        # Input loop
        local key kkey
        zcurses timeout stdscr 200  # 200ms polling for SIGWINCH workaround (per CONTEXT.md)

        while true; do
          if zcurses input stdscr key kkey; then
            case $key$kkey in
              q) break ;;
              # Phase 13 will add: UP/DOWN/LEFT/RIGHT/j/k/h/l/s/d/x/o
            esac
          fi
          # Timeout branch: check resize flag (Phase 14 will fully implement)
        done
      } always {
        # Cleanup ALL windows (use zcurses_windows array like tetriscurses)
        _td_interactive_cleanup_windows
        echoti cnorm                # show cursor
        zcurses end                 # restore terminal (alt screen, echo, etc.)
      }
      ```
    - TRAPINT handler NOT needed inside the always block -- zcurses end in always handles Ctrl+C cleanup automatically (tetriscurses pattern). The `always` block runs on ANY exit including signals.

    **4. Window creation helper `_td_interactive_create_windows`:**
    - Calculate layout from $LINES and $COLUMNS
    - `local num_cols=${#_TD_UI_STATUSES[@]}`
    - `local col_width=$(( (COLUMNS - 2) / num_cols ))` -- leave 1 char margin each side
    - Create header: `zcurses addwin header 1 $COLUMNS 0 0`
    - Create each column: `zcurses addwin col$i $col_height $col_width $col_y $col_x`
      - col_height = LINES - 2 (header + statusbar)
      - col_y = 1, col_x = (i-1) * col_width
    - Create statusbar: `zcurses addwin statusbar 1 $COLUMNS $((LINES - 1)) 0`
    - Store window names in `_TD_UI_WINDOWS=()` array for cleanup

    **5. Window cleanup helper `_td_interactive_cleanup_windows`:**
    - Loop `_TD_UI_WINDOWS` array, `zcurses delwin` each
    - Use `${delwins:*zcurses_windows}` intersection pattern from tetriscurses to only delete existing windows
